# 硬门槛与一票否决

硬门槛是**在评分之前**执行的过滤。不满足的岗位直接淘汰，不进入五维评分。

道理很简单：一个岗位就算内容再对口、公司再好，如果是单休，你也去不了。让它进入评分环节，
只会用一个漂亮的高分来干扰判断。

## 默认硬门槛

### 1. 双休（一票否决）

**单休、大小周、月休 4 天、明确写「加班为常态」的，一律淘汰。**

这是最容易被忽略、也最影响长期生活质量的一条。招聘信息里的表述往往很委婉，要留意这些信号：

- 直接写「双休」→ 通过
- 写「单休」「大小周」「轮休」「月休 4–6 天」→ **淘汰**
- 写「弹性工作」「不打卡」→ 不代表双休，需另行核实
- 完全没提 → 标「双休待核实」，**排到该线末尾**，不得放进首推位

「没提」和「没有」是两回事，不要混为一谈，但也不能让未核实的岗位占着最显眼的位置。

### 2. 通勤时长（一票否决）

从居住地到公司，**单程超过阈值的淘汰**。默认阈值 45 分钟，地铁优先。

必须实测，不能靠地图直线距离估。查询方式：用地图服务搜「<出发地> 到 <详细地址> 通勤 多久 地铁」，
会直接返回多条方案和耗时。取最优方案的时长。

注意「详细地址」要具体到办公园区或门牌，很多公司在多个区都有办公点，
只写公司名会查到错误的那个。

### 3. 城市白名单

只推目标城市内的岗位。接受远程办公与否要提前问清楚 —— 默认排除纯远程岗。

### 4. 永久排除名单

以下情况直接跳过，不进候选：

- 目标方向之外的岗位类型（例如明确只想做设计，就不要推纯销售/BD）
- 已停止招聘或已过期的岗位
- 经营异常、被投诉虚假宣传、有欠薪记录的公司
- 已经在黑名单里的公司

## 边界情况的处理

### 信息缺失怎么办

| 情况 | 处理 |
|---|---|
| 硬门槛字段查不到 | 不淘汰，但标「待核实」并排到末尾 |
| 查到了但不达标 | 直接淘汰，不评分 |
| 多渠道说法冲突 | 以官方渠道为准，冲突本身作为风险提示写出来 |

### 门槛调整

阈值应该随实际反馈调整，但**调整要留痕**。例如通勤从 40 分钟放宽到 45 分钟，
就要在配置里改掉并记住原因，否则过两周会忘记当初为什么放宽。

改门槛是正常的，凭心情改就是灾难。

## 输出要求

被淘汰的岗位不要默默丢掉。日报里要留一段「筛除说明」，写清楚：

```
今日候选 26 个，其中：
- 单休/大小周淘汰 7 个
- 通勤超 45 分钟淘汰 5 个
- 非目标城市淘汰 3 个
- 重复岗位淘汰 4 个
最终入围 7 个
```

写下这些数字，用户才知道规则真的在跑，而不是被随便筛掉了。
