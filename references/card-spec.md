# 岗位卡必填字段

每一张推荐出去的岗位卡，都要包含下面全部字段。**缺一个都不算合格。**

这个清单存在的意义：让用户在打开日报的 30 秒内就能决定「投不投」，
而不用再点开三个网站查一遍。

## 字段清单

### 1. 投递网址 / 官网

必须是**能直接发起投递**的链接，不是公司首页。

优先官方渠道：招聘官网 → 官方招聘公众号链接 → 官方邮件入口。

### 2. HR 投递邮箱

查到就写出来；查不到写「邮箱待核实 · 走官网」，**禁止留空**。

留空的后果是用户还得自己再找一遍，等于这张卡白做了。

### 3. 薪资待遇

照抄招聘信息里的原始表述，**不要换算成「到手多少」** —— 换算涉及社保基数、公积金比例、
个税，任何换算都是猜测。

如果只写了区间，就写区间。如果完全没写，写「薪资未注明」。

### 4. 通勤

格式：`约 X 分钟 · 地铁 N 号线`。

必须是从用户实际出发地实测的结果，不是地图直线距离。详细地址要具体到办公园区。

### 5. 双休情况

三档明确标注，不能含糊：

- `双休 ✅` —— 招聘信息明确写了
- `单双休 ⚠️` —— 写了大小周/单休
- `待核实 ❓` —— 没提到

注意：标 `待核实` 的岗位要排在该线末尾，不能放首推位。

### 6. 社保情况

`五险一金 ✅` / `六险一金` / `五险无一金` / `待核实 ❓`

有些岗位写「五险一金」，但实际是按最低基数缴，这一点归到口碑部分说明。

### 7. 综合评分

写总分 + 五维明细，例如：

```
综合 84｜匹配 88 · 公司 80 · 工作 85 · 福利 78 · 应届 90 · 口碑 75
```

明细一定要写。只给总分，用户没法判断这个分数为什么高、风险在哪。

### 8. 为什么适合（一句话）

必须点到用户的**具体经历**，不能写「岗位匹配度高」这种废话。

```
✅ 你做过 8 个垂类账号的独立运营，这个岗位要的就是能一个人扛起账号矩阵的人
❌ 你的经历与岗位要求高度匹配
```

### 9. 风险提示

如实写。没有风险就写「暂无明显风险」，不要为了凑内容编一个。

常见风险：双休未注明、社保基数存疑、岗位描述与实际职责可能不符、近期大量招人。

### 10. 投递材料清单

按方向列出这次投递该附什么，例如：

```
材料：简历（运营向） + 作品集链接 + 账号清单
```

提前写清楚，用户投的时候不用再去想带哪份简历。

## 卡片模板

```markdown
### 公司名 · 岗位名

- **城市**：成都 · 高新区天府五街
- **投递**：<官网链接>
- **邮箱**：hr@example.com
- **薪资**：8-12K
- **通勤**：约 38 分钟 · 地铁 1 号线
- **双休**：双休 ✅
- **社保**：五险一金 ✅
- **评分**：综合 84｜匹配 88 · 公司 80 · 工作 85 · 福利 78 · 应届 90 · 口碑 75
- **为什么适合**：你独立运营过 8 个垂类账号，这个岗位需要一个人扛起账号矩阵
- **风险**：双休未在 JD 中明写，已通过员工评价侧证
- **材料**：简历（运营向） + 作品集链接 + 账号清单
```

## 自检

出卡前逐条核对：**这 10 个字段里，有几个是空的？**

超过 0 个就不能算合格。查不到的字段写「待核实」也算填了，但**绝对不能默默省略**。
