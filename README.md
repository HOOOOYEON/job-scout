# job-scout

一个帮你决定「今天该投哪几个岗位」的 Agent Skill。

把刷招聘 App 的盲目投递，换成一套有硬规则、有分数、有证据的筛选流程。

## 解决什么问题

找工作最耗人的不是投递本身，是**筛选**。每天几百个岗位，真正能投的可能就三五个，
但你要花两小时才能把它们挑出来，还经常漏掉或重复投。

常见的翻车方式有三种：

- **分数好看但根本不能去**。岗位内容很对口，结果是单休，或者通勤要一个半小时。
- **同一家公司投了两次**。换个平台换个链接，看起来就像个新岗位。
- **把别人的差评当成这家的**。搜公司名出来一堆负面评价，仔细一看是另一家同名的。

job-scout 针对这三件事各有一套硬规则。

## 四个核心设计

### 1. 硬门槛在评分之前

单休、大小周、通勤超时 —— 这些条件不达标，岗位**直接淘汰，不进入评分**。

为什么不给高分留个机会？因为一个去不了的岗位，分数再高也是噪音。
让它进评分，只会用一个漂亮数字干扰判断。

如果招聘信息里**没提**双休，不淘汰，但会标「待核实」并**排到末尾** ——
「没提到」和「没有」是两回事，但也不能让它占着最显眼的位置。

### 2. 六维加权评分

综合分不是拍脑袋，是六项加权：

```
综合分 = 匹配 25% + 公司 20% + 工作 20% + 福利 15% + 应届 10% + 口碑 10%
```

每个维度单独打 0–100，并且**要能说出理由**。权重的作用是压制「某一项特别亮就想去」的冲动。

默认及格线 80 分。名额是上限不是任务量，只有 3 个达标就给 3 个，绝不拿低分岗位凑数。

### 3. 去重必须多表联查

这是踩过坑的地方。

岗位进入系统的路径不止一条，其中**「用户自己在别处看到岗位，回来登记已投」**这条，
只会留下投递记录，不会出现在推荐或岗位记录里。

只查后两者做去重，这些岗位在系统里就像不存在，会在几天后被当成新岗位重推一次。
曾经因此把三个两天前刚邮件直投的岗位当成新岗位推了出去——同一家公司短期内
收到两封同样的投递，是很难挽回的印象。

所以去重必须取**三个来源的并集**，且匹配用「公司 + 岗位 + 城市」的组合键，
因为同一个岗位在不同平台上的 URL 完全不一样。

### 4. 口碑必须确认归属才能采信

中文公司名高度相似，搜索还会把「只是页面上出现了相似的字」的结果一起返回。

**无法确认归属的评价，一律标「未查到该公司专属评价」，宁可写没有，也不编。**

把不明归属的负面评价安到目标公司头上，比信息不全糟糕得多 ——
用户可能因此放弃一家本来不错的公司。

## 快速开始

需要 Python 3.9+，无第三方依赖。

```bash
# 单个岗位评分
python scripts/score.py score --input job.json

# 批量筛选
python scripts/score.py filter --input jobs.json --output result.json

# 生成去重键
python scripts/score.py key --company "示例科技有限公司" --title "AI视觉设计师" --city "成都"
```

岗位数据的字段格式见 `examples/sample-jobs.json`。

跑一遍示例：

```bash
python scripts/score.py filter --input examples/sample-jobs.json
```

会输出类似：

```
候选 5 个 → 入围 2 个，淘汰 2 个（及格线 80）

筛除说明：
  - 通勤超时：1 个
  - 双休不达标：1 个
```

跑测试：

```bash
python -m unittest discover -s tests -v
```

## 作为 Agent Skill 使用

把整个目录放进你的 Skill 目录，然后让 Agent 读取 `SKILL.md`。

`SKILL.md` 是主入口，定义了触发条件、执行流程和硬性边界；
`references/` 下的六个文件是各环节的细则。

典型的触发说法：

```
帮我跑今天的求职日报，方向是 AI 视觉和内容运营，城市成都，
从天府广场出发通勤不超过 45 分钟，单休的不要。
```

## 设计原则

- **不猜数字**。薪资、双休、社保、通勤都要有来源，查不到就写「待核实」。
- **不编口碑**。确认不了归属就写「未查到」，宁缺毋滥。
- **不凑数**。名额是上限，不足就如实说不足。
- **不越界**。只做筛选和日报，不填表、不点提交、不发邮件。

## 常见问题

**为什么我的岗位综合分很高却被淘汰了？**

因为它踩了硬门槛（单休或通勤超时）。硬门槛在评分之前执行，被淘汰的岗位不参与评分，
你看到的分数只是「如果它能去」的参考值。

**及格线 80 是不是太高？**

可以调。`score.py` 的 `--threshold` 参数，或 `SKILL.md` 里改默认值。但**调过之后要固定住**，
否则每天的清单没有可比性。

**双休那栏怎么填？**

`double`（明确双休）、`single`（单休）、`big_small`（大小周）、`rotating`（轮休/月休）、
`unknown`（招聘信息没提）。除了 `double` 和 `unknown`，其余都直接淘汰。

**能直接帮我投递吗？**

不能，这是刻意的。这个 Skill 只产出「可以投了」的清单，投递动作由你自己完成。
